## 7. 架构决策记录

### 7.1 为什么 Agent 批量化
原始 1 段落 1 次 API → 90 段落 = 90 次串行调用 → 3-4 分钟。改为 15 段落/次 → 6 次调用 → 2-3 分钟。

### 7.2 为什么需要 600s 超时
引擎默认 `default_timeout: 30000`，SDK 默认 `invocation_timeout_ms: 30000`。Agent 路径需要 2-3 分钟，三处都需改为 600s。

### 7.3 为什么 trace_id 不嵌套
iii 引擎对同一 worker 内的 `trigger()` 调用创建独立 trace（非 child span）。跨 worker 调用会延续 trace。这是引擎当前行为，非 SDK bug。

### 7.4 为什么用 config.json 而非 configuration worker
iii 的 `configuration::set/get` 用于 iii 自身 worker 注册，`docx-audit` 没有注册 schema（NOT_FOUND）。因此用本地 `config.json` 持久化业务配置。
